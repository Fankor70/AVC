# AVC-Anime — Electron-оболочка (EXE)

Владелец постоянной сессии YummyAnime и хост Next.js UI.

## Архитектура аутентификации

```
Next.js UI (рендерер)
   │  window.avcElectron — ТОЛЬКО не-секретные снимки (contextBridge, preload.cjs)
   ▼
main.cjs → AuthenticationService (auth/authentication-service.cjs)
   │  BrowserWindow в session.fromPartition('persist:yummyanime')
   ▼
Постоянный профиль на диске: <userData>/Partitions/yummyanime
   │  cookie сайта живут здесь и переживают перезапуск приложения и ПК
   ▼
old.yummyani.me — реальный вход (пароль/капча/2FA — только на сайте)
```

- Cookie НИКОГДА не читаются, не логируются и не передаются в рендерер/Next API.
- Состояние входа определяется ВНУТРИ страницы сайта: same-origin `GET /api/profile`
  (401 гость / 200 залогинен) + DOM-маркеры сайта (`#current_user_id`,
  `#user_nickname`, `.logout-btn`, форма входа). Селекторы — только в
  `auth/yummy-auth-adapter.cjs` (секция 23 спеки).
- Успешный вход детектируется event-driven (навигация/DOM + safety-net опрос),
  не «по клику кнопки» (секция 25).
- Выход выполняется САМИМ САЙТОМ (`POST /api/profile/logout` внутри сессии,
  fallback — клик настоящего `.logout-btn`), затем обязательная перепроверка.
- Не-секретный снимок аккаунта — `<userData>/yummy-account.json` (0600).
- Сброс сессии: бэкап каталога профиля → `*.backup-<ts>` → пересоздание
  (секция 22; подтверждение — в UI двухшаговое).

## Разработка

```bash
# 1. Next.js UI (из корня проекта):
bun run dev          # порт 3000
# 2. Оболочка (из этой папки):
npm install
npm run start:dev    # AVC_APP_URL=http://localhost:3000
```

## Диагностика аутентификации (секции 9/20/24)

```bash
npm run auth:test    # JSON-отчёт в stdout; exit 0 — ок, exit 2 — сайт недоступен
```

Или из UI приложения: Отладка → «Диагностика входа YummyAnime» →
«Запустить тест аутентификации».

## Сборка portable EXE (Windows)

```bash
# из корня проекта:
bun run build        # next build (standalone) + статика
# из этой папки:
npm install
npm run dist         # → dist/AVC-Anime-Portable-1.0.0.exe
```

extraResources упаковывает `.next/standalone` + `.next/static` + `public`;
при запуске EXE сам поднимает Next-сервер на свободном порту и ведёт БД в
`<userData>/db` (копируется при первом запуске).

## Ручная тест-матрица (спецификация, секция 19)

| Тест | Шаги | Ожидание |
|---|---|---|
| A — Вход | Аккаунт → «Войти через YummyAnime» → войти в окне сайта | Окно закроется само, чип «Connected», имя |
| B — Неверный пароль | Ввести неверный пароль в окне сайта | Toast «Сайт сообщил о неверном логине…», вход НЕ засчитан |
| C — Перезапуск | Выйти из EXE, запустить снова | Пользователь остался залогинен |
| D — Выход | Аккаунт → «Выйти» | Сайт logout → состояние loggedOut |
| E — Нет сети | Отключить сеть | Кеш не портится, сообщение «Сайт недоступен» |
| F — Сайт недоступен | Заблокировать yummyani.me | «Сайт недоступен», НЕ «неверный пароль» |
| G — Капча | Дождаться капчи при входе | Toast «Пройдите проверку в окне сайта», мониторинг продолжается |
| H — Истечение сессии | Дождаться истечения на сайте | SESSION_EXPIRED («Сессия истекла») |
| I — Несколько аккаунтов | Войти другим аккаунтом | Локальные данные (lastWatched) не смешиваются |
| J/K — Рестарты | Перезапуск рендерера/приложения | Постоянный профиль переиспользуется |
| L — Обновление | Заменить EXE той же версией userData | Сессия сохраняется |
| M/N — AdBlock | Вкл/выкл блокировщик | Вход работает (блокируется только adfinity) |
| O — Голос | «проверь аккаунт», «открой профиль», «выйди из аккаунта» | Команды работают без доступа к секретам |
