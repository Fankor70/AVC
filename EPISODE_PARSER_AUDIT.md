# EPISODE_PARSER_AUDIT — корневой разбор проблемы счётчиков (Task ID: audit-main-1)

Симптомы пользователя: «Наруто показывает ~57–58 вместо 220», «One Piece не сходится».

## 1. Живая проверка источника (октябрь 2026, curl) — ДАННЫЕ ПОЛНЫЕ

| Проверка | Результат |
|---|---|
| `GET /api/anime/111` (Наруто) | `episodes {count:220, aired:220}`; HTML страницы: «Количество серий: 220» |
| `GET /api/anime/111/videos` | 1793 записи, **220 уникальных эпизодов 1..220** (по 2–3 плеера на эпизод), озвучки: 2x2(220), Субтитры(220), AniDUB(220), AniRise(135), Дублированная(103), … |
| `GET /api/anime/1512` (One Piece) | `episodes {count:0, aired:1180}` (онгоинг: считает aired) |
| `GET /api/anime/1512/videos` | 8714 записей (≈5 МБ), эпизоды 1..1180 |
| Пагинация `/videos` | **ОТСУТСТВУЕТ** — всё одним ответом (подтверждено и бандлом YummyTV) |
| Через приложение `/api/site/anime/111` | `episodesAired:220`, 1793 видео — путь сервера отдаёт всё |

Вывод: **сервер и адаптер данные не теряют. Хардкод запрещён и не нужен.**

## 2. Полный путь данных (трассировка)

```
сайт /api/anime/{id}(+videos)
 → adapter.getVideos/getAnimeById → buildDetails (episodesAired=d.episodes.aired)
 → /api/site/anime (proxy, force-dynamic)
 → клиент fetchDetails → detailsCache (executor.ts:50, БЕЗ TTL)
 → maxEpisodeOf(details) (executor.ts:197)
 → UI: сетка Array.from({length:maxEp}) (anime-view.tsx:265), чипы озвучек ({d.episodes.length}) (247), MiniPlayer «Серия X/{episodesAired}» (65)
```

## 3. Корневые причины видимого «58» (ранжировано, все проверены кодом+живьём)

1. **ГЛАВНАЯ — viewport сетки эпизодов**: контейнер `max-h-64 overflow-y-auto` (anime-view.tsx:264) ≈ 4–5 строк; при `lg:grid-cols-12` (кнопка 44px + gap ≈ 52px) видно **48–60 кнопок** — отсюда «~57–58». Внутренний скролл недоступен голосу: `executeScroll` скроллит только `#avc-content` (executor.ts:904) — голосовой пользователь физически не добирается до эпизодов дальше первого экрана.
2. **Per-dub счётчик читается как общий**: чипы показывают `{d.episodes.length}` — у One Piece есть озвучки ровно на **58** эпизодов (LE-Production; Макс Летов & ShiYori — проверено живьём). Выбор такой озвучки делает «58 эпизодов» в диалоге эпизодов.
3. **Таймаут 12с на 5-МБ `/videos`** (adapter.ts:93): обрыв → `getVideos→[]` → fallback на `translates` с **пустыми списками** эпизодов → клик «Серия N» = «не найдена». На медленной сети выглядит как «серий мало/список сломан».
4. **Кэш без инвалидации**: клиентский `detailsCache` живёт всю сессию; «Обновляю страницу» НЕ обходит его (getCachedDetails короткое замыкание, anime-view.tsx:44) — устаревшие детали не обновляются до рестарта.
5. Не причина (проверено и исключено): смешение сезонов/OVA (адаптер игнорирует viewing_order, глобальная нумерация корректна для Naruto/OP); пагинация (её нет); БД (эпизоды не кэшируются в SQLite); player-параметры (Kodik/Alloha пинятся на эпизод корректно).

## 4. Раздельная модель сущностей (спека §23) — как будет

- **Anime** = карточка `/api/anime/{id}` (`episodes.count/aired` — счётчик основного сериала).
- **Episode** = `number` (строка, парсить в int) из `/videos`, глобальная нумерация.
- **Special/OVA/ONA/Movie/SpinOff/Related** = отдельные записи каталога (свои id), связаны через `viewing_order`/франшизу — НЕ входят в счётчик серий.
- **Franchise/WatchOrder** = `viewing_order` деталей (+ `#view-list-button` на странице) — отдельная структура «Порядок просмотра», клик открывает реальную страницу тайтла.
- Запрещено смешивать: episode count ≠ franchise entries ≠ watch-order positions.

## 5. Чек-лист исправления (без хардкодов)

- [ ] anime-view: сетка эпизодов без «спрятанного» скролла — пагинация по ~60/страница + «показать все» в диалоге; голосовая прокрутка внутренних контейнеров (executor).
- [ ] Счётчики честные: «Серий: 220 · озвучка 2x2 — 220 эп.» (per-dub только как уточнение, не как общий итог).
- [ ] adapter: таймаут для `/videos` ≥ 25с + 1 ретрай; кэш с ограничением размера; `source: 'live'|'demo'` → бейдж DEMO в UI.
- [ ] executor: detailsCache с TTL 5 мин + инвалидация по «Обновляю страницу».
- [ ] Регресс-тесты (текстовые, без сети): maxEpisodeOf для count/aired/онгоинг; парсинг `number:"12"`; дедуп плееров на эпизод; per-dub группировка.
- [ ] Приёмка на живом сайте: Наруто=220, One Piece=1180, +3 структуры (многосезонный, онгоинг, с OVA/фильмами) — проставить PASS/FAIL честно.

## 6. Версионирование кэша (спека §25)

Вводится `EPISODE_PARSER_VERSION` (константа в adapter) — входит в ключ кэша; при изменении парсера версии инвалидаются автоматически. Клиентский кэш: TTL + версия + `stale-while-revalidate` (показать мгновенно из кэша, обновить в фоне, бейдж «обновлено только что»).
