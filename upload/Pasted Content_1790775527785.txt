MAJOR ARCHITECTURE TASK: LOW-LATENCY VOICE COMMAND SYSTEM WITHOUT FALSE COMMANDS OR COOLDOWN PROBLEMS

The current voice system has a serious UX problem:

The user says something.

The application reacts immediately.

Sometimes the user was NOT giving a command.

Then the user repeats the actual command, but the application is still inside a cooldown period, so the second command is ignored.

This must be redesigned.

DO NOT simply reduce the cooldown.

The system needs intelligent command validation, debouncing and command lifecycle management.

==================================================
1. PRIMARY GOAL
==================================================

The voice system should feel:

- immediate
- responsive
- natural
- low latency
- resistant to accidental speech
- able to accept a command immediately after an incorrect recognition
- able to handle repeated commands

There should NOT be a long global cooldown.
