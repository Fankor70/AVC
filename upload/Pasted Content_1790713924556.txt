# Задача

Создай полноценное Windows 10 desktop-приложение для управления сайтом YummyAnime голосом, предназначенное для использования с дивана без необходимости постоянно брать в руки мышь и клавиатуру.

Рабочее название приложения:

**Anime Voice Controller**

Главная идея:

Пользователь запускает приложение, перед ним появляется удобный GUI с встроенным браузером. Внутри приложения открывается YummyAnime.

Пользователь может управлять сайтом голосом:

* открыть аниме;
* найти аниме по названию;
* открыть TOP-100;
* открыть каталог;
* открыть онгоинги;
* открыть расписание;
* открыть анонсы;
* открыть случайное аниме;
* перейти назад/вперёд;
* открыть новую вкладку;
* закрыть вкладку;
* переключить вкладку;
* выбрать аниме;
* выбрать серию;
* перейти на следующую серию;
* перейти на предыдущую серию;
* перемотать видео;
* поставить на паузу;
* продолжить воспроизведение;
* изменить громкость;
* полноэкранный режим;
* выбрать озвучку;
* искать аниме голосом;
* сказать номер серии и автоматически открыть её;
* произносить русские команды естественным языком.

Приложение должно работать максимально автономно и удобно.

---

# 1. Целевая платформа

Основная платформа:

**Windows 10 64-bit**

Также желательно обеспечить совместимость с:

* Windows 11 x64.

Программа должна запускаться как обычный `.exe`.

В финальной версии должна быть возможность собрать:

* `.exe`
* portable version
* желательно installer

Не требовать от пользователя устанавливать Visual Studio или Python.

---

# 2. Предлагаемый технологический стек

Используй наиболее стабильный стек для Windows desktop.

Предпочтительный вариант:

* C#
* .NET 8 или актуальная стабильная версия .NET, совместимая с Windows 10
* WPF
* Microsoft WebView2 для встроенного браузера
* MVVM architecture

Если есть веская техническая причина использовать другой UI framework, объясни её перед реализацией.

Основное предпочтение:

**WPF + WebView2 + C#**

Почему WebView2:

Приложение должно иметь встроенный браузер, а не просто запускать внешний Chrome.

Нужно иметь возможность:

* загружать страницы;
* выполнять JavaScript внутри страницы;
* получать URL;
* получать title;
* взаимодействовать с DOM;
* нажимать элементы;
* менять элементы;
* получать информацию о текущей серии;
* взаимодействовать с HTML5 video;
* перехватывать события страницы.

---

# 3. Очень важное требование

НЕ создавай систему, которая зависит исключительно от координат мыши.

Плохой вариант:

"нажать x=500 y=300".

Хороший вариант:

* DOM selectors;
* JavaScript injection;
* поиск HTML элементов;
* keyboard events;
* WebView2 APIs;
* MutationObserver;
* анализ URL;
* анализ DOM;
* HTML5 video API.

Координатное управление мышью можно добавить только как fallback.

Причина:

Сайт может изменить размер окна, разрешение, масштаб интерфейса или расположение элементов.

Приложение должно быть максимально устойчивым к изменениям сайта.

# 9. Голосовой движок

Сделай голосовой слой абстрактным.

Например:

```csharp
interface ISpeechRecognitionService
{
    Task StartAsync();
    Task StopAsync();
    event Action<string> SpeechRecognized;
}
```

Основной движок желательно сделать через локальное распознавание речи.

Рассмотри:

* Whisper;
* faster-whisper;
* whisper.cpp;
* Windows Speech Recognition.

Приоритет:

**локальная обработка голоса без отправки постоянного аудио в облако.**

Если для первой версии Whisper слишком сложен, реализуй рабочую Windows Speech Recognition версию, но архитектуру сделай такой, чтобы Whisper можно было подключить позже.

3. открывает поиск;

6. показывает результаты.

Другие варианты:

> "Найди Стального алхимика"

# 15. Нечёткий поиск

Название аниме может быть распознано неправильно.

Например пользователь говорит:

> "Стальной алхимик братство"

Speech-to-text может вернуть:

> "Стальной алхимик братство"

или:

> "Стальной алхимик братство"

или ошибочный вариант.

Нужно использовать fuzzy matching.

Можно применять:

* Levenshtein distance;
* normalization;
* lowercase;
* удаление пунктуации;
* словарь известных названий.

Не требовать идеального совпадения.

# 23. Важная особенность плеера

На странице конкретного аниме плеер загружается через iframe.

Поэтому система должна учитывать iframe.

На исследуемой странице YummyAnime плеер находится через iframe, а сайт отдельно отображает доступные варианты озвучки.

Архитектура должна предусматривать:

```text
WebView2
    ↓
YummyAnime page
    ↓
iframe
    ↓
video player
```

Если iframe относится к другому origin и прямой JavaScript-доступ невозможен из-за политики браузера, НЕ ломай приложение.

В таком случае использовать:

* URL/navigation detection;
* keyboard shortcuts;
* postMessage, если доступно;
* WebView2 frame APIs;
* DOM взаимодействие родительской страницы;
* доступные элементы управления;
* fallback keyboard control.

# 107. Контекстные сокращения

Если пользователь уже смотрит сериал:

> "Десятая"

понимать как:

> "Открыть 10 серию текущего аниме"

Если он говорит:

> "Дальше"

понимать:

> "Следующая серия"

Если говорит:

> "Назад"

в контексте видео:

> "Предыдущая серия"

Но если пользователь находится на обычной странице:

> "Назад"

→ browser Back.

То есть команда должна учитывать текущий контекст.

# 109. Не использовать AI API для каждой команды

Обычные команды должны работать локально.

Не отправлять каждую команду в ChatGPT/OpenAI API.

Parser должен быть:

* быстрым;
* локальным;
* детерминированным.

AI/LLM можно добавить позже как optional advanced parser.

Например если пользователь сказал:

> "Поставь мне следующую серию того аниме, которое я сейчас смотрю"

локальный parser может попытаться обработать это через intent matching.

Но базовые команды должны работать без API.
