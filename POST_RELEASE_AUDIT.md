## 1. Голосовое управление в EXE (критично)

**Воспроизведение:** свежая portable-сборка → разрешить микрофон → говорить →
статус «Слушаю…» навсегда, стенограммы нет, истории нет, ошибок нет.

**Пайплайн (как есть):** `use-voice.ts` выбирает движок по `settings.sttEngine`
(`types.ts:445` → дефолт `'auto'`):
1. `'auto'` → Web Speech API (`webkitSpeechRecognition`). В Chromium/Electron
   без ключей Google-речевого бэкенда распознавание либо молча не возвращает
   результаты, либо падает — классическая причина «вечного listening».
2. Фолбэк `'server'` → `MediaRecorder` → `POST /api/voice/asr` →
   `ZAI.create()` (`z-ai-web-dev-sdk`). В dev-контейнере SDK авторизован —
   поэтому «в вебе работает». В packaged standalone на машине пользователя
   кредов/конфига SDK нет → 500 → распознавания нет.
3. Правильный для EXE движок `'local'` (IPC → AI-воркер на чистом Node с
   sherpa-onnx STT + Silero VAD, модели в комплекте манифеста) — реализован
   полностью (`startLocalSession`, feed/flush, partial/final, early-command),
   но **не выбирается автоматически** и не является дефолтом.

**Root cause:** несоответствие дефолтов средам: packaged-сборка стартует на
`'auto'`, а её работоспособный путь — `'local'`.

**Исправление (план):**
- Детект среды: при наличии Electron-моста дефолтный движок = `'local'`
  (однократная миграция настройки для существующих пользователей).
- Состояния пайплайна (6.2): Disabled/Initializing/MicDenied/WaitingMic/
  Listening/SpeechDetected/Recognizing/Partial/Final/Processing/Error —
  с таймаутами и понятными статусами вместо вечного «Слушаю».
- Тишина ≠ молчание: «речь слышна, но текст не распознан», «аудио не
  поступает» — отдельные статусы (6.4/6.5).
- Восстановление: смена устройства/отвал микрофона/краш воркера →
  ограниченные ретраи + кнопка «Перезапустить голосовой сервис» (6.6).
- Диагностика: корреляция событий пайплайна (permission → device → samples →
  VAD → partial → final → intent → action), панель диагностики, copy-отчёт (6.3/6.7).

**Тест:** локальные самотесты STT/TTS/LLM (нативные линукс-бинарники уже в
репо, круговой прогон TTS→STT выполняется `--ai-selftest`); в packaged EXE на
Windows — **blocked by environment**, сравнение dev/packaged задокументировать.

## 2. Ручные команды / распознавание тайтлов

**Воспроизведение А:** ввести `наруто` → «Неизвестная команда».
**Воспроизведение Б:** открыт Блич → ввести `наруто 1 серия` → играет серия 1
Блича.

**Root cause А:** `parseSegment` все экстракторы требуют триггер
(`найди/открой/включи…`); голый тайтл не матчится нигде → `failed:true`.

**Root cause Б:** `extractEpisodeSelect`, паттерн 2 (`parser.ts:530-542`):
ищет число+«серию» по ВСЕМУ сегменту; слова перед числом («наруто»)
молча выбрасываются → `SelectEpisode(1)` → `playEpisode()` строит плеер от
`st.playback.animeId` (текущий Блич). Явный тайтл никогда не доходит до резолва.

**Исправление (план):**
- Новый экстрактор `<тайтл> <N> серия` → составная команда
  `SearchAnime{query, open:true, episode:N}`; исполнитель: резолв тайтла →
  навигация → выбор серии внутри НАЙДЕННОГО аниме.
- Голый тайтл (fallback, последним шагом) → `SearchAnime{query, open:true}`.
- `включи <тайтл> первую серию` — разбиение хвоста триггера на тайтл+эпизод.
- Приоритет контекста: явный тайтл > выбранное в UI > текущее аниме >
  уточняющий вопрос (4.3). Блич-тест обязателен.
- Неопределённость → диалог вариантов (уже есть `pendingOptions`),
  автоперый-результат только при score ≥ 0.55 и единственности/уверенности.
- Общие статусы результата (4.7): ищу → нашёл → открыл → серия X; отдельные
  ошибки: не найдено / несколько совпадений / серия не найдена / сайт недоступен.

**Тест:** таблица §9.1 (Наруто, Блич 20, Шиппуден 10, следующая/5 серия…)
прогоном парсера+исполнителя (unit) + через UI в браузере; Naruto-тест при
открытом Бличе — обязателен в обоих входах (текст и голос-симуляция).

## 3. Медленный запуск EXE

**Факты:** таймингов в `main.cjs` нет вовсе (ни одного perf-маркера).
Портативный EXE — NSIS-архив ~385 МБ: при каждом запуске распаковывается в
%TEMP% (поведение portable-таргета electron-builder) — доминирующая стоимость
холодного старта, особенно на HDD. AI-воркер форкается асинхронно (окно не
блокирует), но грузит модели сразу при старте воркера.

**Исправление (план):** структурные метки времени (perf.now) на всех этапах
(process → ready → окно → UI-загружен), JSON-отчёт старта в лог; LLM/необязательные
сервисы — лениво; отчёт до/после. Честно: числовые замеры на Windows —
**blocked by environment**; методика замера приложена.

## 4. AI-модели: папка и менеджер

**Факты:** `model-manager.cjs` качает по манифесту с sha256/структурой (хорошо),
но `baseDir` = `AVC_MODELS_DIR` env → `userData/ai-models`; выбора папки нет,
миграции нет, в UI (ai-setup-dialog 255 строк) пути не показываются.

**Исправление (план):** IPC: выбор каталога (диалог ОС), миграция
(проверка места → копирование → sha256-сверка → атомарное переключение конфига →
откат при ошибке; старая папка не удаляется до успеха), recovery-диалог при
недоступном диске; секция «AI-модели» в настройках: имя/назначение/версия/статус/
путь/размер/загружен ли/обязательность + действия (скачать/починить/удалить/
открыть в проводнике/сменить папку).

## 5. Адаптивность панели команд

`w-72` скрыта < lg; футер = VoicePanel + MiniPlayer в ряд (sm:flex-row).

## 6. Тема Navy Blue

**Факты:** токены shadcn в `globals.css` (oklch) — zinc/нейтральные; акценты
amber-400 захардкожены в компонентах (voice-panel, mini-player, header-bar…).
План: палитра из ТЗ → CSS-переменные (тёмная Navy по умолчанию), перевод
захардкоженных акцентов на токены, контраст-проверка, скриншоты до/после
по ключевым экранам.
